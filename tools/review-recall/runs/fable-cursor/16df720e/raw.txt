I've now read everything the push touches and the machinery it leans on. Here is my assessment before the verdict.

**What the push does.** Five new tests in `src/completion_queue.zig` pin the claim protocol's edges (close-claims-drained, close-vs-claim race, cancelAll conservation, canceled-select claim delivery per #700, teardown quiescence via struct poisoning), plus a new externally-driven death-test example `cq_two_driver_misuse.zig` registered in `build.zig`. The tests' assertions match the actual contracts: `select.zig` does deliver a claimed winner on the canceled path (#700), `close()` does claim the drained state to a parked select, and `ownerCallback`'s signal `fetchAdd` sits inside the critical section, which is exactly what the poison test watches. `JoinHandle.cancel()` blocks until completion, so the example's frame lifetimes are sound. `ExecutorCount.exact(4)` and the `main(std.process.Init)` example shape are all real.

**What I'd raise.**

1. Nothing executes the death test. The example's whole point is its exit behaviour ("Exit 0 means the misuse was silently accepted, which is the failure this example exists to catch"), and the commit message says "a harness runs it and checks for a NON-zero exit" — but no such harness exists in the tree. `zig build examples` only builds it, and `check.sh --full` (which CI runs) already contains the exact pattern needed — it runs `stderr-smoke --panic` and fails if it does not abort — yet the new example was not wired in. A regression back to silent acceptance is invisible to every gate. Also, "any non-zero exit" is a weak oracle: an incidental error return from `main` also exits non-zero, so the run should grep the panic message.

2. The `cancelAll(.keep)` conservation test claims a race it structurally cannot produce. It uses `Runtime.init(std.testing.allocator, .{})`, and `RuntimeOptions.executors` defaults to `.exact(1)` — one executor, no worker threads. Its comment says operations are "completing on the loops right now (their callbacks racing the drain)", but with a single executor there is one loop and every `ownerCallback` runs on the same thread as `cancelAll`, only while the drain is parked. The commit's stated target for this test ("claim vs cancelAll's drain") is exercised only as cooperative interleaving, never concurrently. The teardown test shows the author knows the fix: `.executors = .exact(4)` plus spreading submissions.

3. The canceled-select test has no cleanup on its failure paths. In the `error.Canceled` branch, if the `expectEqual` on `err` fails or the 5-second `timedWait` times out, the test returns with `mail.c` potentially still pending in the queue and armed with the loop — pointing into the test's popped stack frame. The straggling callback then writes through `c.group.owner` into dead stack while the runner continues, turning one failure into cascading corruption. Every neighboring test defends against this with `defer cq.cancelAll(.discard)`; the new round-based tests do not.

4. The poison watch is expensive for the power it buys. 200 rounds × 500 scans × ~sizeof(CompletionQueue) individual `std.testing.expectEqual` calls is on the order of 10 million try-wrapped byte comparisons per backend, and the suite runs per backend (up to four per job) across the CI matrix including QEMU-emulated targets under a 10-minute job timeout. The test's own comment concedes that at the real gap width a pass "is one more clean sample". A `std.mem.allEqual` scan or fewer iterations gives the same witness at a fraction of the cost.

I considered and rejected: the example's fast-path window (two drivers can both consume via the ready fast path without panicking — but the 5s window makes park overlap effectively certain, and the doc claims only that the second *registration* panics); mutex-memory quiescence after the drain (unlock's release store happens-before the drain's final acquire, and `Futex.wake` takes only an address on all three OS families); `@TypeOf(try rt.spawn(...))` (valid, unevaluated); the 0-microsecond timer durations; and stale futex wakes crossing rounds (drain re-checks on every wake).
