The push adds `CompletionQueue.isClosed()` so a select driver can tell a real `error.Closed` from the spurious one `getResult` still has to return. `wait()` only yields `error.Closed` when the queue is closed **and** drained; `getResult` returns `error.Closed` whenever `completed` is empty. `close()` does not wake while operations are still pending, but a leftover select signal can still claim the arm in that state. The new helper only samples `closed`, and nothing tests the protocol.
