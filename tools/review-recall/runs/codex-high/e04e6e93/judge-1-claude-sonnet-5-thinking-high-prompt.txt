title: Executor tick retune now reads a pre-callback timestamp and can over-inflate the quantum budget.
`tick_now` now comes from `self.loop.now()`, but `Loop.poll` refreshes that snapshot before running async/cancel/work completion callbacks. The retune window therefore excludes callback time, so under callback-heavy cycles `elapsed / n` is underestimated and `tick_task_budget` drifts upward (often toward `max_tick_budget`), delaying subsequent polls and increasing timer/I/O latency. Use a fresh monotonic read here (or move the loop snapshot refresh to the end of `poll`) so the retune window matches actual cycle wall time.
