# Fable round 2 (condensed record of the subagent hand-back, written by the panel owner)

Step 0 (from memory): fixed request_scratch_bytes slab (64 KiB) rented per request from a server-wide SlabPool of max_streams_per_server slabs, lowest free bit, counted once, FixedBufferAllocator with OutOfMemory past budget, rented at header lease or slot claim and returned at release, plus Response.bodyWriter() streaming into the stream slab. (Matches round 1.)

## D1: pool. [LOGIC] Under glibc the metered shape lowers RSS only if every arena node is an mmap (page_allocator: syscalls + fresh faults per request, one VMA per live node, nears vm.max_map_count 65,530 at 1024 x 32 x 1-3 nodes) or with malloc_trim / M_MMAP_THRESHOLD=0 (process-wide, heap walk). glibc's mmap threshold starts at 128 KiB and grows (to 32 MiB) after large frees, so arena nodes stop leaving RSS. Pool weak point answered: on return, madvise(MADV_DONTNEED/MADV_FREE) the pages above FixedBufferAllocator.end_index when it exceeds ~16 KiB: one syscall only on rare large requests. Without it: resident <= concurrent requests x pages written, already capped by max_streams_per_server. Rent at HPACK decode so the (rung-4 unreachable) exhaustion maps to refused_stream, unlike today's DATA slab exhaustion which turns into a failed write (connection.zig:4238-4242) despite slab_pool's "backpressure" comment. Cost: one CAS per rent and release.

## D2: 256 KiB (changed from 64): under a pool the budget is virtual (4096 x 256 KiB = 1 GiB virtual); datastar.zig parses signals into req.arena and request_body_bytes is 256 KiB. Boot check request_scratch_bytes >= decoded_header_bytes + header arrays. [PREMISE: vm.overcommit_memory=2 must size the pool down.] Output: Response.bodyWriter() (its buffer is the render buffer; subsumes Grok's second rented buffer); per-event scratch: mark/reset on the bump allocator (Astra's render scope, cheap). 200 KiB SSE fragment: writer drains via writeCb into the 64 KiB stream slab, parks in waitForStreamSpace, actor emits 16 KiB quanta fairly, slab freed when drained; 0 bytes left in the request slab after reset; nothing allocates.

## D3: per-connection write chunks via SlabPool (WIRE_CHUNK_SIZE, capacity 4), lowest free bit (1-2 touched chunks instead of rotating 8), GPA fallback removed; same for the read pool. Reasons [LOGIC]: the wake already exists (pump return = write ack, actor consumes acks; h2c pause hook = "free write chunks < 2", mirroring TLS pause at connection.zig:3194-3198 and pushes_per_pop = 2); a server-wide pool needs cross-connection wakes (lock or fan-out on every return); a per-connection pool backpressures only the connection that caused it.
Encode DATA straight into the leased chunk. Grok's objection fails: encoding into the lease is not in-place in the DATA slab, and a scratch copy does not protect the debit today either (sendAccountedWire can fail after the debit at :4983, :4987, :5007; drainEmit fails closed). Real fix (Astra): reserve the destination before the debit: lease or pause, then buildData debits, copy header+slice, hand off (the lease is the capacity proof); move tryReserveOutboundBytes before buildData too. Delete plaintext_scratch (-16 KiB/conn) and the false "queueWire encrypts this borrowed slice synchronously" comment (:4515-4517).

## Changed mind: budget 64 -> 256 KiB; added mark/reset scope; SlabPool instead of LIFO queue; resident = concurrent x pages written, madvise stops it persisting.
